# Capture pipeline — VictoryShield.exe Screen Accountability capture, scheduler, and screenstate handoff

Scope: `VictoryShield.exe` (27,191 fn, image base `0x140000000`) capture path: the `PdlEdi` scheduler that triggers `PdlEdi::captureScreenstate`, the DXGI capture chain (cross-ref `re/findings/15-ui/ui-architecture.md` §5 for the D3D11/DXGI init verdict), and — the core question — what a "screenstate" is and how it reaches `VictoryShieldClassifier.exe`. Non-goals: classifier-binary internals (deferred to the classifier pass, see Open questions), general UI topics. Cross-refs: `re/findings/12-network/filter-surface.md` §7 (circumvention producer), `re/findings/02-artifacts/classifier-data.md` (per-SID tree, launch contract, `pdl-edi`/`bundleManager` log tags).

## What it does

`VictoryShield.exe` is the **screenstate producer**. On a self-rescheduling timer it captures **every monitor** via DXGI Desktop Duplication (DX9 fallback), stitches the monitors into one screen image, encodes each monitor's pixels as a **PNG**, and hands the whole capture to the classifier as a **file transaction**: a timestamped folder under `C:\ProgramData\CovenantEyes\Classifier\<SID>\data\pdl\` containing per-monitor image files (`im<N>.dat`), a JSON manifest (`ss.dat`, schema `3.0.0`), and a 0-byte ready marker (`rr.dat`); the classifier is woken through the named event `PdlNotifyARE`. Restricted windows (apps that set `WDA_EXCLUDEFROMCAPTURE`-style display affinity) are not skipped or blacked by CE — they are logged as "Possible circumvention", recorded to the `circumventions` table, and tagged `doNotScore: true` in the screenstate's `apps[]` array so the classifier ignores their regions. The cadence comes from backend config (`/v1/member/sensor/config/pdlEdi` → `imageScreenshotInterval_sec` ± `imageScreenshotIntervalVariance_pct`) and capture only runs while the session is unlocked (WTS events) and the classifier process is alive.

## Mechanism

### 1. Capture scheduler — trigger sites and cadence

**Trigger: a periodic task, not window/activity events.** `PdlEdi` runs a table of type-erased periodic tasks, each returning `Maybe<std::chrono::duration<__int64, std::ratio<1,1000>>>` (i.e. an optional next-run delay in **milliseconds**; RTTI text of the task functor inside `FUN_1402d7690`). Three tasks are visible, each a `<lambda>` thunk in `PdlEdi.cpp`:

| task (log name) | thunk | worker | notes |
|---|---|---|---|
| `check PDL notifications` | `FUN_1402d6c10` | `PdlEdi::handlePdlNotifications` | waits on `ClientNotifyARE`/`ClientNotifyProcARE` |
| `check PDL folder consistency` | `FUN_1402d6d50` | `PdlEdi::handlePdlFileNotifications` | directory-watch for transaction tampering |
| `capture screenstate` | `FUN_1402d6e90` | `PdlEdi::captureScreenstate` = `FUN_1402d7690` | the capture trigger |

The `capture screenstate` task is also invocable directly through a `CVictoryShieldView` adapter (`FUN_1402b8790` — pulls the `PdlEdi` instance from `view+0x4f0` and calls `FUN_1402d7690`; [INFERENCE] the on-demand path behind `createScreenAccountabilityReportBatchASAP`/"Score Now"). The generic loop that dispatches the task table and sleeps per returned duration is a type-erased scheduler; its exact function was not pinned (see Open questions), but every cadence number the loop can use is produced by the capture task itself.

**Cadence/trigger table** (values written into the returned duration by `PdlEdi::captureScreenstate::<lambda_1>::operator()` = `FUN_1402d3600`, and by the wrapper `FUN_1402d7690`):

| condition | next capture in | evidence |
|---|---|---|
| capture gate false (classifier not running / not ready) | **5 000 ms** retry | `FUN_1402d3600` prologue: `*param_2 = 5000`, early-out on `FUN_1402d7f00` |
| gate ok but no user / `isDisplayOn` false | **5 000 ms** (value already set) + log `Skip capturing Screenstate` | `FUN_1402d3600` (`"Skip capturing Screenstate"` `0x1408df730`) |
| captured, but no `PdlInfo` row loaded | **40 000 ms** default | `FUN_1402d3600`: `*param_2 = 40000` |
| lambda produced no value | **60 000 ms** | `FUN_1402d7690`: `FUN_140213190(uVar11, 60000)` |
| normal steady state | **uniform in [(1−v)·I, (1+v)·I]** where `I = imageScreenshotInterval_sec × 1000` ms, `v = imageScreenshotIntervalVariance` (fraction) | `FUN_1402d3600` tail: `dVar9 = *(int*)(pdlInfo+0x10)*1000; fVar2 = *(float*)(pdlInfo+0x14); … = rand * ((fVar2+1)*dVar9 − dVar10) + dVar10` |
| WTS lock (7) / logoff (6) | capture **gated off** until unlock/logon | `FUN_1402b7580` |
| screen saver running at capture time | transaction fails → `saver_while_capture` telemetry, retry per table above | `FUN_1402d5d30` (`"System Screen Saver is active while taking screen shot"` `0x1408df5f8`) |

So the nominal cadence is **backend-controlled** (default 40 s when no config is present), jittered by ±`imageScreenshotIntervalVariance_pct` to de-synchronize clients. The interval parameters arrive with the PDL config fetch: endpoint `/v1/member/sensor/config/pdlEdi` (`0x140a4f888`), parser `pdlSettingsParser` (`0x140a4fb70`), keys `imageScreenshotInterval_sec` (`0x140a4fbc8`), `imageScreenshotIntervalVariance_pct` (`0x140a4fbf0`), stored in the `pdl_info` SQLite table columns `imageScreenshotInterval`/`imageScreenshotIntervalVariance`/`pdlVersion`/`pdlData` (`0x140a3e250`–`0x140a3e318`).

**There is no idle detector.** No `GetLastInputInfo`-style input-idle probing exists in the binary (string/import sweeps negative); a user being idle does not change the cadence. The only runtime gates are the session/display flags, the screensaver check at capture time, and the classifier-alive check:

- `PdlEdi::isClassifierRunning` = `FUN_1402db800`: finds processes owned by the current system user (RTTI `findProcessesRunningWithOwner`, `0x140b31230`; `get system username owning PID` `0x140a47148`), logs `"Classifier is still not detected running for system user: "` / `"Classifier is detected running, but probably not yet ready…"` / `"Classifier is detected running for system user: "` (`0x1408df228`/`0x1408df270`/`0x1408df2c0`).
- `PdlEdi::isDisplayOn` = `FUN_1402dc560`: returns `flag(+0x60) && flag(+0x61)` — display-on **and** session-on. `PdlEdi::setSessionOn` = `FUN_1402de120` (PdlEdi.cpp line `0x12e`) writes `+0x61` and logs `"setSessionOn : true|false"`; `PdlEdi::setDisplayOn` = `FUN_1402dda40` writes the other flag (callers `FUN_1402c5d00`, `FUN_1402b5df0`).

**WTS session gating** (`CVictoryShieldView::OnWtsSessionChange` = `FUN_1402b7580`; registered via `WTSRegisterSessionNotification`, failure log `"Unable to register for WTS Session Notifications, error: "` `0x1408dd4e0`):

| 5 `WTS_SESSION_LOGON` | "A user has logged on to session ID: N" (`0x1408dd220`) | `true` |
| 6 `WTS_SESSION_LOGOFF` | "A user has logged off from session ID: N" (`0x1408dd248`) | `false` (+ `FUN_1402beba0` teardown) |

**Multi-monitor handling: all monitors, stitched + per-monitor files.** `Win32DxgiCapture::initializeD3d` (`FUN_140280940`) enumerates all adapters (`"Number of display adapters detected: "` `0x140a51148`) and all outputs per adapter (`"Number of monitors detected: "` `0x140a51078`; `IDXGIOutput6` QI for color space, `"QueryInterface for IDXGIOutput6 failed"` `0x140a50f18`). `ce::screencapture::WindowsScreen::captureScreenshot` = `FUN_140286100` loops per monitor (its loop logs both scopes `Win32DxgiCapture::captureMonitor` `0x140a512b8` and `WindowsScreen::captureScreenshot` `0x140a51820`), captures each monitor (`captureMonitorDx11` `FUN_140283fe0` / `captureMonitorDx9` `FUN_140282a80` / `captureMonitorDx11WithFallback` str `0x140a514f0`), saves each to its own file (`im` + monitor index + `.dat`, strings `im` `0x140a4229c`, `.dat` `0x140a51854`; index itoa at `FUN_140286100`+`0x286484`…`0x28652b`), and composes one screen image (`"captureScreenshot origin=("` `0x140a517b0`, `"captureScreenshot screenImage w="` `0x140a517f8`). **HDR tone-map path.** Per monitor, `Win32DxgiCapture::getColorSpace` (str `0x140a50eb8`) reads the output color space (the `IDXGIOutput6` QI above) and `Win32DxgiCapture::toneMap` = `FUN_1402822b0` converts HDR textures before saving: log strings `"convert fixed point HDR texture to floating point"` (`0x140a518c8`), `"tone map floating point HDR texture"` (`0x140a518a0`), `"convert floating point HDR texture to fixed point"` (`0x140a51918`); failures `"Failed to tone map image"` (`0x140a512e0`) / `"Failed to evaluate image"` (`0x140a513a8`). [INFERENCE] Triggered on HDR10 (PQ/P2020) surfaces so the saved PNG is tone-mapped SDR.

### 2. Screenstate pipeline + handoff — VERDICT

**What one capture produces** (call chain `PdlEdi::captureScreenstate` → lambda `FUN_1402d3600` → `PdlEdi::createScreenstateTransaction` `FUN_1402d8400` (PdlEdi.cpp `0x1ee`) → worker `FUN_1402d4bd0`):

1. `ce::pdledi::createTransactionFolder` = `FUN_1401adc70` creates `C:\ProgramData\CovenantEyes\Classifier\<SID>\data\pdl\<ts>` — path segments `"CovenantEyes"`/`"Classifier"`/`"data"`/`"pdl"` (`0x140a42340`/`0x140a42330`/`0x140a422b0`/`PTR_DAT_140b29b30`→`"pdl"` `0x140a42328`), SID via `"acquire SystemUserID for Classifier Data folder"` (`0x140a422e8`, RTTI `getClassifierDataFolderPath` `0x140b31040`). Folder name = `FilenameCompatibleDateTimeFormatter` with `"%Y-%m-%dT%H-%M-%S"` + sub-second fraction, and on name collision a `-0`…`-9` suffix is appended (loop in `FUN_1401adc70`, `"Transaction folder name collision: "` `0x140a42388`). This exactly matches the observed dir `…\data\pdl\2026-09-20T04-55-17.3281948-0\` (`classifier-data.md`).
2. `ce::pdledi::captureScreen` = `FUN_1402ed5f0(out, folder, username, deviceId)` captures the desktop (`Screen` singleton `FUN_14027b2c0` → `captureScreenshot` writes `im0.dat`, `im1.dat`, … into the folder), enumerates windows, and reports restricted windows (§3).
3. `FUN_1402ee610` writes **`ss.dat`** — the screenstate **JSON manifest** — into the folder. Keys built in order (all decompiled):
   - `$schema: "./screenstate_schema.json"` (`0x1408e0fa8`), `schemaVersion: "3.0.0"`, `urlSafeUsername` (url-safe encoding of the username), `datetime_created`, `local_utc_offset`;
   - `images: [ { filename: "imN.dat", screenRect: [l,t,w,h] } ]` (`FUN_1402eec10`; entries are 48 B: 4 ints + filename string);
   - `monitors: [ … ]` (`FUN_1402eeef0`);
   - `apps: [ { name, window_title, appRect, doNotScore? } ]` (`FUN_1402ed3a0`; keys `"name"` `0x140a3efe8`, `"window_title"` `0x1408e0f58`, `"appRect"` `0x1408e0f68`, `"doNotScore"` `0x1408e0f70`);
   - `clientPayload: { device: … }` (`"clientPayload"` `0x1408e1020`, `"device"` `0x1408e0f9c`, `"device_uuid"` `0x1408e0f90`).
   The JSON is serialized (`FUN_140220300`) and written to `<folder>\ss.dat` (`FUN_1401ad860`).
4. `PdlEdi::markPdlReady` = `FUN_1402dcc80` (PdlEdi.cpp `0x167`) creates the 0-byte **ready marker `rr.dat`** (`FUN_1401ab730` — the only `rr.dat` writer; `rr.dat` string `0x140a4226c`) and then notifies the classifier (`FUN_1402dd170`, [INFERENCE: sets the `PdlNotifyARE` named event — the event name `PdlNotifyARE` `0x140a42378` is opened by the pdledi event accessor `FUN_1401adc20`; the client-side notify helpers are `PdlEdi::notifyPdlIfNeeded`/`notifyPdlWithDeadline` with `"PDL notify response timeout"` `0x1408df3d8`). Failure ⇒ log `"Mark folder ready error"` and the transaction throws `"Mark Pdl ready error"`.

**VERDICT — the screenstate handoff mechanism is FILE-BASED: per-capture transaction folders on disk in the classifier's per-SID `data\pdl\` tree, completed by a `rr.dat` ready marker and a named-event wakeup (`PdlNotifyARE`). Not shared memory, not the Boost.Interprocess queues, not HTTP.**

Evidence ruling out the alternatives:
- **Files (positive):** the full chain above writes `<folder>\imN.dat` (PNG), `<folder>\ss.dat` (JSON), `<folder>\rr.dat` (marker) — `FUN_1402d4bd0` calls `FUN_1401adc70` (create folder) → `FUN_1402ed5f0` (capture into folder) → `FUN_1402dcc80` (mark ready) in that order; on capture failure the folder is deleted (`FUN_1401acbe0`) and a `capture_error` telemetry recorded before throwing `"Screen capture error"`.
- **Not shared memory:** the only file mapping in the binary is `CE_SPYMapObj` (filter-state cache, `FUN_1402b3600`; `re/findings/15-ui/ui-architecture.md` §4b) — it carries policy flags/username, never pixels or screenstates.
- **Not the message queues:** `ce_user_event_message_queue`/`ce_service_event_message_queue` carry only the 8-byte-code event vocabulary `0x43..0x55` (UiPass) — no screenstate payload path exists in `FUN_1402cc960`.
- **Not HTTP:** the client's HTTP layer (`ce::pdledi::HttpRequestProcessor`, `AuthProvidedHttpClient`) is used *by the classifier through the client* in the reverse direction (§ "reverse channel" below); nothing POSTs screenstates.

**Transaction file vocabulary** (string cluster `0x140a4226c`–`0x140a422d0`; cleaned at startup by `PdlEdi::cleanFolders` — `"clean PDL send folders"`/`"clean PDL receive folders"` `0x1408df358`/`0x1408df370`; tamper-watched by `PdlEdi::handlePdlFileNotifications` — `"Circumvention: PDL transaction file removed|renamed|unknown action"` `0x1408dfc40`–`0x1408dfcc0`):

**Reverse channel (classifier → client), for completeness.** The classifier does not open sockets; it drops message folders that the client's `ce::pdledi::PdlMessageEngine::processMessages/processFolder` ("PDL-EDI: Processing ready folder" `0x1408e0d40`) dispatches to `CurrentStateProcessor::processMessage` (`PdlCurrentStateProcessor.cpp`) and `HttpRequestProcessor::processMessage` (`PdlHttpRequestProcessor.cpp`) — the latter **executes HTTP GET/POST/PUT/DELETE on the classifier's behalf** ("execute GET for user '…'" `0x1408e0470`, auth `CE_BASIC`/`NO_AUTH` `0x1408e08c8`, `retryPolicy`/`retryWindowSeconds`, template substitution via `replaceValues`/`substituteStrings`) and writes the result back as an `hr.dat` transaction. Wakeups use `ClientNotifyARE`/`ClientNotifyProcARE` (`0x1408dfa48`/`0x1408dfa58`, `PdlEdi::handlePdlNotifications`: `"PDL->Client Notify event detected"`). The classifier's own outputs observed on disk (`data\client\<epoch-ms>\ht.dat`, `classifier-data.md`) use an epoch-ms folder naming instead of the `%Y-%m-%dT%H-%M-%S` format — [INFERENCE] `data\pdl\` is the client→PDL channel (client-created, ISO-named) and `data\client\` is the PDL→client channel created by the classifier's copy of the library.

### 3. Capture restrictions (FUN_1402ed5f0 / restricted windows)

- **Source of the restricted flag — OS window state, not a config list.** `ce::screencapture::WindowsScreen::getWindowList` (`FUN_14027c4f0`) enumerates visible windows per capture (entry stride `0x90`: rect ints at `+0x0..+0x1F`, flag bytes at `+0x20..+0x28`, title string at `+0x30`, app name at `+0x50`, extra strings `+0x70`; `GetWindowTextA` helper `FUN_14027c4f0`-family, filter-surface §7). The restricted test `isWindowContentRestricted` (scope string `0x140a50be0`, inside `FUN_14027c4f0`) is computed from **`GetWindowDisplayAffinity`** (`"GetWindowDisplayAffinity failed:"` `0x140a50c38`) and **`DwmGetWindowAttribute`** (`"DwmGetWindowAttribute failed:"` `0x140a50c60`), with helpers `isCloakedLayeredWindow` (`0x140a50c80`) and `isZeroAreaWindow` (`0x140a50ca0`); the visible-set filter logs `"Window visible ["` (`0x140a50ba8`). The restricted flag is the **byte at entry `+0x28`** (checked as `puVar26[5]` in `FUN_1402ed5f0`'s loop). No config file, no `CE_SPYMapObj` field, and no hardcoded app list feeds this — the negative is structural (the only inputs to the predicate are the Win32/DWM queries). [INFERENCE] `+0x28` is set when the window's display affinity is `WDA_EXCLUDEFROMCAPTURE` (0x11) or `WDA_MONITOR` (0x01), or the window is DWM-cloaked; exact affinity values not decompiled.
- **Effect on the capture — flagged, not skipped/blacked.** For every entry with `+0x28` set, `captureScreen` (`FUN_1402ed5f0`):
  1. logs `"Possible circumvention: Screen capture is restricted for App: <app> with Window Title: <title>"` (`0x1408e1050`);
  2. calls the circumvention recorder `FUN_1402c66a0(view, "windows-screen-recording-not-allowed", title, app)` (`0x1408e0ed0`) → `CECircumventionEntry` → `CircumventionSqliteLogsQueue` → `circumventions` table (full chain in `re/findings/12-network/filter-surface.md` §7);
  3. still includes the window in the screenstate `apps[]` array but with **`doNotScore: true`** (`FUN_1402ed3a0` sets the key when `FUN_1402eeb80` sees flag `+0x24` or `+0x28` set) — i.e. the pixels are captured (Desktop Duplication will show such windows as black content anyway [INFERENCE]) and the classifier is told to exclude the window's region from scoring.
  The whole capture is never aborted because of a restricted window; only zero successful monitors aborts.

### 4. Model data touchpoints — explicit negative

**Model data is exclusively the classifier's. `VictoryShield.exe` contains no `*.dat.enc` filenames, no `b1`/`b2`/`b3`/`j1`/`mn`/`sw` suffixes, and no model-file handling.** String sweeps over the full binary (ASCII + UTF-16, VAs mapped via PE sections) find: no `.enc` strings outside OpenSSL cipher names (`aes-*-cfb1` etc.), no `ht.dat`-style model names except the transaction vocabulary above, and no `nxu`/`bmdat`/`bundleManager` strings at all. The only model-adjacent strings are the classifier **launch arguments** ` --model=`, ` --data=`, ` --cache=`, ` --version=`, ` --verbose` (`0x1408e1330`/`0x1408e1320`/`0x1408e1310`/`0x1408e1340`/`0x1408e1300`) built by `LaunchAndMonitorScreenMonitoring` = `FUN_1402f0a90` (`processlaunch.cpp` line 13) into the command line of `VictoryShieldClassifier.exe` (`0x140a426f8`; launched via `LaunchAndMonitorProcess`/`CECreateProcess` `0x140a42190`, `"launching daemon "` `0x140a421a8`). The `--model=` value is a directory path supplied by `FUN_1401ab5d0` (the install `data` dir — `"data"` segment `0x140a422b0`), consistent with the logged contract `--model="C:\Program Files\CE\data"` (`re/findings/02-artifacts/classifier-data.md`). The client never reads the blobs.

## Linux-reimplementation notes

- The file-transaction handoff ports cleanly: producer writes `spool/<sid>/out/<timestamp>/` with `imN.png` + `manifest.json` + an atomic `ready` marker (or write-to-temp + rename), consumer (classifier) inotify-wakes on the marker. The named-event wakeup is just an optimization; the marker alone is a complete protocol. Preserve the per-message-type file names + startup cleanup + tamper watch (C/E's `Circumvention: PDL transaction file removed` is a nice integrity signal).
- Cadence: fetch `interval_s ± variance_pct` from your config endpoint, sleep uniformly in `[(1−v)I,(1+v)I]`, with fixed short retries (5 s while the classifier is down, 40–60 s fallbacks). Gate on: session unlocked (logind `LockedHint`/`Active`), screensaver not running, classifier process alive (or just make the daemon own the capture itself and drop the second process).
- Screenstate manifest: keep CE's key set (`images[{filename,screenRect}]`, `monitors`, `apps[{name,window_title,appRect,doNotScore}]`, `datetime_created`, `local_utc_offset`, `clientPayload.device`) if you want classifier-side tooling compatibility; `doNotScore` windows marked from the compositor's security-state (Wayland: `securityContext`/X11: `_NET_WM_WINDOW_TYPE`+screensaver surfaces).
- Capture: all monitors, PNG per monitor, per-monitor rotation normalization and an HDR→SDR tone-map step (PipeWire formats are already SDR-normalized in most portals; verify HDR sources). Skip capture entirely on lock/screensaver instead of capturing and marking `saver_while_capture`.
- Model data separation is worth copying: the capture client only passes `--model=<dir>`; blobs stay opaque to everything but the classifier.
